## [Unreleased]

### Fixed

- Fixed `schedule-install` generating a systemd service with a quoted `WorkingDirectory`, which systemd rejects as not absolute, so the hourly sync timer could never start. Services generated by the broken version are still recognized as belonging to their Storage, and reinstalling rewrites them in the fixed form.

## [0.3.1] - 2026-11-09

### Fixed

- Fixed fresh Storage setups not recognizing Framework-provided mise tasks, including search and sync ([#23](https://github.com/Seika139/pkm-framework/pull/23)).

## [0.3.0] - 2026-11-09

### Added

- Added `.pkm/storage.toml` source registration and explicit MCP access profiles that limit search and read access and control Wiki access ([#19](https://github.com/Seika139/pkm-framework/pull/19)).
- Added owner-only Storage enrollment and explicit Wiki policy review commands, with versioned markers, pinned MCP config digests, and fail-closed behavior after policy changes; approval is blocked while existing Topic source references point outside the current Wiki source roots.
- Added source-aware Wiki `source_refs` validation and a sync allowlist derived from registered `sync = true` roots, exact policy files, and the selected Vault layout.

### Changed

- Kept legacy `pkm-storage-vault-v1` Storage behavior when no config is present; Storage with a v2 marker now requires a valid config and never falls back to legacy mode.
- MCP search applies each profile's source permissions before returning results, while the shared index continues to refresh all registered sources.
- Registered source directories may be absent; they are treated as empty so search and MCP startup remain available.

### Fixed

- Configured MCP search now finds accented uppercase text and canonically equivalent Unicode forms regardless of query case or normalization.
- The `storage-policy-review` managed task now accepts both the default report command and the `--confirm` option.
- Storage enrollment and policy review now verify Windows Storage ownership and securely stage replacements while preserving existing ACLs.
- Policy review rejects unsupported multiline `reviewed_policy_hash` values without changing the config, preventing confirmation from leaving invalid TOML.

## [0.2.1] - 2026-10-15

### Fixed

- CLI commands force UTF-8 for stdout and stderr, so `pkm wiki context` and other commands no longer fail with `UnicodeEncodeError` on Windows when output is redirected under a cp932 locale.

## [0.2.0] - 2026-10-15

### Changed

- Framework-managed Storage tasks are now Python file tasks instead of Bash scripts, so they run natively on Windows without WSL. Storage mise configuration must provide Python `3.12` and uv `0.12.23`, and Git must be installed separately for `mise run sync`.
- Schedule tasks now verify that the macOS LaunchAgent or Linux systemd unit was created for the current Storage before reporting status or uninstalling it.
- Storage sync reports a clear error when Git is not installed or not on `PATH`.

### Removed

- Removed the Bash variants of the distributed Storage tasks and scripts (`mise/tasks/*.sh`, `mise/scripts/schedule.sh`, `mise/scripts/storage.sh`); the installer retires previously managed copies from Storage.
- Removed the `grant-permissions` mise task from the Framework development setup; Python file tasks no longer need execute-permission fixes.

## [0.1.4] - 2026-10-15

### Fixed

- Hardened Storage path validation against symbolic links, Windows junctions, and files that are not single-link regular files.
- Improved scheduled-sync task ownership checks and handling of missing systemd user directories.
- Protected Git metadata and rotating sync logs against redirected paths and unsafe file types.
